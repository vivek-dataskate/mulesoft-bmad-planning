The BMAD Pipeline — High Level
From Call Recording to Live Integration
Seven stages. Scout (Stage 1) is fully automated by 9 AI agents. Stages 2–5 are DataSkate-owned. Developer implements in Stage 6, DataSkate verifies in Stage 7.
Stage 1 — Scout · Fully Automated
9 AI Agents. One Pre-Sales Run.
Drop in a call recording (and optionally a deck or notes). Orchestrate.js runs each agent in sequence — each reads the prior agent's output and writes its own. Total wall-clock time: ~15–25 minutes. Output: a complete proposal, intake questionnaire, integration deck, and psychology-adapted talking points. No manual work.

What Scout Produces
Three Client-Ready Deliverables
Every Scout run produces these three artifacts — generated, formatted, and deployed automatically.
Primary Deliverable
Client Proposal
  • Challenge framing adapted to buyer psychology profile
  • Solution diagram — systems connected via MuleSoft
  • Flow-by-flow breakdown with business outcome per flow
  • ROI section with verified benchmarks from Vera research
  • 3-stage AI journey (Connected → Automated → Agentic)
  • FOMO section ordered by buyer's social-proof angle
  • Pricing computed live from tm-rates.json + flow count
  • Timeline and next steps with architect name
Discovery Deliverable
Client Intake Questionnaire
  • Pre-filled answers from what Sage extracted in the transcript
  • Unanswered gaps clearly flagged for the client to complete
  • Use cases collapsed by default — client expands to answer
  • Submits directly to Firestore on "Submit to DataSkate"
  • Deployed to firebase/public/intake/{client}.html
AE Pitch Kit
Integration Deck
  • Geo-first FOMO: named companies within ~100 miles
  • Nearby peers with verified public case studies
  • 4 opening lines for the architect — scripted by Hawk
  • AI journey narrative specific to their systems + industry
  • Talking points adapted to buyer psychology profile
  • Competitor FOMO ordered by social-proof angle
Stages 2–7 — What Follows Scout
The Rest of the Pipeline
Each stage has its own AI agent (or is auto-generated). Sub-agent pipelines like Scout's are planned for later stages as volume grows.
Stage 2
Analyst
Mary (AI)
Reads intake responses. Produces PRD — flows, acceptance criteria, canonical field mapping, edge cases. Validates against canonical-models registry.
Stage 3
Architect
Winston (AI)
Technical design from PRD. Selects connectors, defines API-led layers, sets security level, writes architecture.md and decisions.json.
Stage 4
PM
John (AI)
Converts architecture + PRD into user stories (stories.md). Creates Jira tickets and GitHub issues in the client dev repo. Sets sprint milestones.
Stage 5
Scaffold
Auto-generated
generate.js reads decisions.json and produces a complete Mule 4 project — connector stubs, DWL transforms, MUnit test shells, pom.xml, property files.
Stage 6
Developer
Engineer
Opens scaffold in Anypoint Studio / Code Builder. Fills in TODO flow logic. Runs MUnit. Commits to client GitHub repo. No boilerplate — scaffold handles it.
Stage 7
Verify
Dev agent (VR)
Runs MUnit suite. Checks coverage floors from decisions.json. Verifies every FR and NFR from stories.md is addressed. Produces PASS or gap report.
