# Story Template: Verify Anypoint Visualizer Layer Diagram

**Story Type:** Global Governance
**When to include:** Always — every project, generated once
**Priority:** P1 — complete before UAT begins
**Standard:** `standards/DESIGN_STANDARDS.md → API-Led Connectivity`
**Config File:** `mule-artifact.json` (in project root)

---

## User Story

As a tech lead, I need Anypoint Visualizer to show each API application in the correct layer (System / Process / Experience), so that the architecture is enforced at runtime and any cross-layer violation is visible before UAT begins.

---

## Acceptance Criteria

### Layer Property Configuration
- [ ] `anypoint.platform.visualizer.layer` property set in `mule-artifact.json` for each API application:
  - System APIs (`*-sys-api`): `"System"`
  - Process APIs (`*-proc-api`): `"Process"`
  - Experience APIs (`*-exp-api`): `"Experience"`
- [ ] No application left at the default (unlayered / unclassified) in Visualizer
- [ ] `mule-artifact.json` example format:
  ```json
  {
    "minMuleVersion": "4.8.0",
    "secureProperties": [],
    "configs": [...],
    "tags": ["layer:System"]
  }
  ```
  *(exact property location per Anypoint documentation — scaffold generates this)*

### Cross-Layer Compliance
- [ ] No Experience API calls a System API directly — always via Process API
- [ ] No System API calls a Process or Experience API
- [ ] All cross-API calls go through the correct layer as defined in `architecture.md → API-Led Architecture View`
- [ ] Any violation found during review is flagged as **P0 architecture defect** before UAT begins

### Visualizer Review
- [ ] Application deployed to dev environment
- [ ] Anypoint Visualizer diagram accessed and reviewed in Anypoint Platform
- [ ] Screenshot of Visualizer diagram attached to this story (or linked from Jira/GitHub issue)
- [ ] Diagram matches `architecture.md → API-Led Architecture View` section
- [ ] All flows appear in correct layer

## Implementation Notes

- `mule-artifact.json` is generated by scaffold — developer verifies the `visualizer.layer` value matches the API's role
- Reference: `standards/DESIGN_STANDARDS.md → API-Led Connectivity → Naming`
- Naming rule: `{system}-sys-api` | `{domain}-proc-api` | `{consumer}-exp-api`
- If the project contains only one API application that performs all three roles (uncommon — requires tech lead justification): classify as the dominant role and document deviation in architecture.md
