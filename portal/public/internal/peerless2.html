Corporate Profile

1. Origin & History

Peerless Fence is a specialty fence installation contractor operating in the residential and commercial construction vertical. The company is PE-backed under Akoya Capital and sits beneath a platform holding company called Elevate Fence Partners, which operates a "platform-above" structure — meaning Peerless Fence is a portfolio brand within a broader roll-up thesis. Founded year is not on record; no public website or HQ address has been confirmed. The Akoya/Elevate structure is consistent with the current wave of home-services and specialty-trades consolidation, where a financial sponsor acquires regional operators, standardizes back-office systems, and extracts margin through operational leverage. Peerless Fence is the engagement entity and the operating brand — they are one and the same for our purposes.

The platform context matters architecturally: any automation we build at Peerless Fence may become a template Elevate deploys across sibling brands. There are no confirmed sibling brands on record yet, but the platform-above shape means Kirk's decisions carry upstream implications.

2. Business Model

Peerless Fence installs residential and commercial fencing, sourcing a material volume of its leads through the Home Depot Service Center Portal — a third-party lead referral channel that assigns F-number-keyed leads to contractor partners. This HD Portal dependency is the single most operationally sensitive integration point in the engagement: lead velocity, revenue, and HD partnership standing all hinge on how fast and accurately those leads are processed.

The revenue cycle runs: HD Portal lead → sales consultation → site plan + quote (Salesforce) → contract execution (DocHub, contract types 299A / 299B / 118) → job creation (ComputerEase) → field execution → billing. Deposits are tracked across HD Portal, Salesforce, and ComputerEase — three systems that currently do not talk to each other without manual intervention.

Key business objects in play: Lead, Quote, Customer, Contract, Job, Task, Appointment, Deposit. The absence of a confirmed revenue figure or employee count is consistent with SMB classification, but the PE-backed platform context suggests the company is being managed toward a higher revenue tier.

Material ordering (owned by Barb) and labor scheduling are currently manual downstream of job creation — these are Phase 3 targets but are already creating friction in field execution.

3. Corporate Stack

Five systems are in active scope:

Home Depot Service Center Portal — Lead origination. Leads are keyed by F-number. Currently polled manually by Ashley Salerno each morning. API credentials are controlled by Marius (HD-side developer). A 10-minute polling cadence is the target; webhook availability is unconfirmed and may require negotiation with HD. This is an external dependency — Peerless Fence does not own the API contract.

Salesforce — CRM and quoting layer. Opportunities progress to a "Save as Final" quote status that is the intended trigger for downstream job creation. Admin access and sandbox/production parity need to be verified before integration build begins. A read-only API user for ComputerEase sync is a prerequisite not yet provisioned.

ComputerEase (Deltek) — ERP and job costing system. This is the most technically constrained system in the stack. API access requires enabling the CE Live Service relay, which is a Deltek vendor-side action — a support ticket to Deltek is a hard prerequisite. API version compatibility must be confirmed at v26+. Jean Jacobs administers ComputerEase and is the internal owner of this prerequisite. Job numbering in ComputerEase follows a sequential scheme keyed by company code + product line + initials — this logic must be replicated exactly in the automation.

Google Cloud Platform (GCP) — Infrastructure host for the ComputerEase VM. Current firewall rules are insufficiently hardened (SSH/RDP exposure flagged). Network isolation for the CE VM and a secure API gateway for inbound integrations are required before any API traffic flows. Brian Cook owns this layer.

DocHub — Digital signature capture for contract types 299A, 299B, and 118. Document storage and retrieval API must be configured for Salesforce integration. This is the contract validation backbone for Phase 2.

No legacy bolt-ons are on record. The stack is relatively clean for an SMB, which is a positive signal for integration velocity once prerequisites clear.

6. Strategic Position

Peerless Fence is a PE-backed specialty contractor in the middle of a systems modernization that was likely accelerated by Akoya's acquisition thesis. The HD Portal dependency is both a revenue concentration risk and a competitive moat — HD contractor partnerships are not freely available, and the ability to process HD leads faster than competing contractors directly affects win rate and HD scorecard standing.

The three-phase AI journey maps cleanly onto the revenue cycle: Phase 1 secures the lead funnel, Phase 2 closes the quote-to-job gap, Phase 3 operationalizes field execution. Each phase has a discrete ROI story: Phase 1 = lead response time and Ashley's manual hours; Phase 2 = job entry accuracy and contract compliance; Phase 3 = material and labor efficiency.

The FOMO profile is operational-pragmatist — this buyer responds to concrete workflow relief, not abstract AI narratives. Peer analogues confirm the pattern: a comparable fence group has already built the HD Portal → Salesforce scheduled poll and the Salesforce "Save as Final" → ComputerEase job creation flow. These are not hypothetical — they are proven patterns we can reference directly in the engagement.

The AgileMind analogue (Salesforce → QuickBooks invoice automation) is a weaker but relevant reference for the financial sync story in Phase 2, particularly for Laura and Stephanie's accounting workflow.

7. Signals to Watch

CE Live Service relay ticket status — This is the single longest-lead prerequisite. If Deltek's support queue is slow, Phase 2 slips. Jean Jacobs needs to open this ticket immediately; we should confirm it is open within the first week of engagement.

HD Portal API credential timeline — Marius is an external dependency at a large enterprise (Home Depot). Vendor onboarding and API credentialing at HD can take weeks. If this is not already in motion, Phase 1 is at risk. Escalate through Greg if Marius is unresponsive.

GCP firewall remediation — Brian Cook's infrastructure work is a prerequisite for any inbound API traffic to ComputerEase. If this is deprioritized against other IT work, the entire integration stack is blocked. Monitor closely.

Salesforce sandbox parity — If the Salesforce sandbox does not mirror production configuration, integration testing will produce false positives. Verify this before build begins.

Elevate platform visibility — If Akoya/Elevate is actively evaluating Peerless Fence as a template for other portfolio brands, the timeline pressure on this engagement increases. Conversely, if Elevate is hands-off, Kirk has more flexibility. Clarify the platform's involvement level.

DocHub contract type coverage — Contract types 299A, 299B, and 118 are named, but it is not confirmed whether all active contract variants are covered. Any undocumented contract type discovered during Phase 2 build will require scope adjustment.

The PE-backed platform context is the strategic upside. If we execute Phase 1 cleanly and visibly, Kirk has a story to tell at the Elevate level. That is the path from a three-phase SMB engagement to a platform-wide program. Build for Peerless Fence; architect for Elevate.
