Internal Technical Flags — Do Not Send to Client

1
Auth model: Salesforce = OAuth JWT (service account). QB = OAuth 2.0 Authorization Code with refresh token stored in CloudHub Secrets Manager. QB realmId stored in Secrets Manager — not in property files.
2
QB update pattern: QBO API has no PUT/PATCH. All updates via POST with full object + current SyncToken (retrieved via GET immediately before each POST). See FK-017.
3
QB token refresh (FK-017): Access tokens expire hard at 60 minutes. MuleSoft QBO connector handles refresh automatically when configured with refresh token. For batch flows exceeding 60 min, implement 401-detect → refresh → retry wrapper.
4
QB version gate: If Q4.1 answer is anything other than “QuickBooks Online (cloud)” — STOP and escalate to Kailash immediately. QB Desktop requires QBXML + Windows Web Connector — completely different architecture. See FK-020.
5
Google Sheets: Use service-account auth (no user OAuth prompt for unattended flow). Sheet must be shared with DataSkate service account email before development begins.
6
Salesforce trigger for UC1: Prefer Platform Event or Change Data Capture (CDC) on Agreement__c over polling. Requires Chloe to confirm CDC is enabled in their Salesforce org (Q5.4).
7
ISBN lookup table: Custom Metadata Type recommended. Supports runtime update without code deployment. Kailash proposed; Maria agreed. Kailash will send field spec to Chloe.
8
Inventory committed/available: Must be calculated in the integration layer or Salesforce (QOH - committed = available). Committed quantity is derived from open Agreement line items — not directly available from QB.
9
Back-to-school deployment risk: Go-live target July 15, 2026. Back-to-school fulfillment peaks July–August. If anything slips past July 1, recommend rescheduling to September. Cutover: Tuesday early AM CT with Crystal and Maria on standby.

P0 escalation path: All 4 P0 blockers (QB version, QBO plan tier, SF Inventory__c creation, QB OAuth consent) must be resolved in the intake questionnaire response before any architecture work begins. If any P0 is unresolved by requirements kickoff, the project start date must slip.
