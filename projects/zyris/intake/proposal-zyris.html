The Challenge

Three Systems. No Single Source of Truth.

Zyris manages dental practice relationships across HubSpot, processes orders in Dynamics 365 Finance & Operations, and sells through Shopify — but today these systems don't talk to each other in any meaningful way. The result is manual data re-entry, stale customer records, and an operations team that can't trust what any single system shows.

Challenge 1

Shopify orders don't flow automatically into D365 FO. Every online dental equipment order requires manual re-entry into the ERP — a repetitive, error-prone process that slows order-to-cash and scales linearly with order volume.

Challenge 2

HubSpot and D365 FO maintain separate views of the same dental practice. When a rep updates a contact in HubSpot, D365 FO doesn't know. When FO closes an order, HubSpot doesn't reflect it. Reps have to reconcile both systems manually before every customer call.

Challenge 3

Pricing agreements and customer tiers managed in FO or HubSpot don't propagate to Shopify customer tags. When an agreement changes, someone has to manually update Shopify — or the wrong pricing rules apply at checkout.

Challenge 4

HubSpot record merges silently corrupt cross-system links. When two Company records are merged in HubSpot, the Dynamics 365 Customer ID and Shopify Customer ID on the losing record are lost — breaking order history and pricing associations without anyone knowing.

The Solution

MuleSoft as the Central Integration Hub

DataSkate builds and manages a MuleSoft integration layer that sits between HubSpot, D365 FO, and Shopify — synchronizing customer records, routing orders, preserving external IDs through HubSpot merges, and keeping pricing tags current. Every flow follows the same API-led connectivity architecture: System APIs for each application, a Process layer for business logic, and Experience APIs for external triggers.

6 flows across 3 systems. Bidirectional where noted — all flows managed through the central MuleSoft hub. Zyris-owned code in GitHub from day one.

Proposed Integrations

6 Flows Across HubSpot, D365 FO, and Shopify

Each flow follows MuleSoft's API-led connectivity pattern — System API for raw system access, Process API for business logic and transformation, Experience API for inbound triggers. All DataWeave mapping code is delivered to Zyris's GitHub repository.

UC1a Medium
HubSpot → D365 FO Customer Sync (Batch)
HubSpot Companies → D365 FO Customers · Scheduled
Scheduled batch job queries HubSpot for Companies modified since last run (watermark pattern). Upserts matching D365 FO Customer records. Stamps FO Customer ID back to HubSpot for cross-system linkage. Note: D365 FO PATCH implemented via HTTP connector fallback (FK-005).
UC1b Medium
HubSpot → D365 FO Customer Sync (Real-Time)
HubSpot CRM trigger → D365 FO Customer · On-demand
A "sync now" action in HubSpot triggers immediate sync of a single Company record to D365 FO — enabling reps to force-sync before a customer call without waiting for the next batch window. Same upsert logic as UC1a.
UC2a High
Shopify → D365 FO Order Sync
Shopify orders/create webhook → D365 FO SalesOrders
New Shopify order triggers MuleSoft webhook receiver. Address normalization logic (per Zyris flowchart) identifies the matching D365 FO customer. FO SalesOrder created; Shopify Order ID stamped in FO for linkage. FO SalesId written back to Shopify. Highest complexity flow — address normalization document is a P0 prerequisite.
UC2b Medium
D365 FO → Shopify Order Status Sync
D365 FO SalesOrder status → Shopify fulfillment
Scheduled poll of D365 FO for orders with status changes since last watermark. Updates Shopify fulfillment status (Delivered → fulfilled, Cancelled → cancelled). Dental practices see accurate delivery status on their Shopify account. Depends on UC2a (requires Shopify Order ID stored in FO).
UC3 Medium
HubSpot Merge Event → External ID Preservation
HubSpot company.merge webhook → HubSpot + D365 FO
Receives HubSpot merge webhook when two Company records are merged. Extracts D365 Customer ID and Shopify Customer ID from the losing record. Stamps both IDs onto the winning record in HubSpot — ensuring cross-system links are never silently broken by a merge operation.
UC4 Medium
Pricing / Sales Agreement → Shopify Customer Tags
D365 FO or HubSpot pricing change → Shopify customer tags
Detects pricing agreement or customer tier changes in D365 FO (CustomerGroup) or HubSpot (custom property). Updates the corresponding Shopify customer tags so pricing rules and discount scripts automatically reflect the current agreement — eliminating manual Shopify tag maintenance.
