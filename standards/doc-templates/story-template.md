### {CLIENT}-{NNN} — Configure Global Error Handler and DLQ

**Type:** Infrastructure
**Epic:** {client}-mule Setup
**Priority:** P0 — must complete before any flow goes to dev
**Standard:** `standards/DESIGN_STANDARDS.md → Error Handling`
**Scaffold File:** `src/main/mule/error-handler.xml`

**User Story:**
As a developer, I need a global error handler that catches all unhandled exceptions, formats a standard error envelope, routes to DLQ after max retries, and never exposes stack traces, so that every integration flow has consistent failure behavior without per-flow error-handling code.

**Acceptance Criteria:**

- [ ] `error-handler.xml` exists at `src/main/mule/error-handler.xml`
- [ ] Global error handler catches `ANY` exception type
- [ ] Error envelope emitted on every error path: `{correlationId, errorCode, message, timestamp, failingComponent}`
- [ ] No Java stack trace appears in any error response or log line at WARN or above
- [ ] DLQ routing configured: after {N} retries with {exponential/fixed} backoff → publish to `{dlq-name}`
  - Async MQ retries: exponential 30s / 90s / 270s → DLQ
  - Sync API retries: 3 × 5s fixed → return 503 + Retry-After header
- [ ] MANUAL ack mode on all MQ consumers — ACK only after successful processing
- [ ] Notification failures (Slack/email/SMS) wrapped in `on-error-continue` — NEVER break primary flow
- [ ] Notification retry: 2-3 retries, fixed 2-5s, log WARN on final failure, continue always
- [ ] `error-handler.xml` referenced as global in all `{domain}-flows.xml` files
- [ ] Validation failures route to `{domain}-invalid-messages-queue` BEFORE any downstream call (not DLQ)
- [ ] MUnit test: verify error envelope schema on simulated ANY exception

**DLQ Config:**
```
Queue: {dlq-name}
Max Retries: {N} (default 3)
Backoff: exponential — 30s / 90s / 270s
MANUAL ack: yes
```
